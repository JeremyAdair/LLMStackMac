1. Core runtime layer

This is the core runtime that keeps the system functional.

Examples:

  • Ollama: Runs local model inference.
  • Open WebUI: Provides the main user chat interface.
  • Postgres: Stores structured application data.
  • Qdrant: Stores and retrieves vectors for semantic search.

If it cannot serve requests, store data, or retrieve indexed content, it belongs here.

2. Platform services layer

This is the stuff that supports the runtime.

Examples:

  • Reverse proxy: Routes incoming web requests to the right service.
  • Authelia: Handles authentication and access control.
  • Redis: Provides fast cache and queue primitives.
  • Python-runner: Executes utility scripts and automation tasks.
  • File storage: Keeps persistent files and uploads available.
  • Background job services: Process long-running tasks asynchronously.

These are support systems that keep the runtime secure and stable.

3. Observability layer

This is how you inspect and understand the system.

Examples:

  • Prometheus: Scrapes and stores time-series metrics.
  • Grafana: Visualizes metrics in dashboards and panels.
  • pgAdmin: Inspects and manages PostgreSQL state.
  • Logs: Provide event history and troubleshooting context.

This is your historian / HMI layer.

4. Automation and tooling layer

This is where the stack starts doing repeatable useful work.

Examples:

  • Flowise: Builds and runs workflow-based automations.
  • Python-runner scripts: Execute repeatable utility workflows.
  • Ingestion jobs: Import and preprocess source content.
  • Export jobs: Package and move results out of the stack.
  • Summarizers: Generate condensed outputs from larger inputs.
  • Maintenance scripts: Perform routine operational upkeep.

This is where your runner makes sense.

5. Experimental layer

This is the stuff you are testing, learning, or may remove later.

Examples:

  • Temporary agents: Short-lived experiments under evaluation.
  • Test containers: Trial services used for validation.
  • Scratch integrations: In-progress connector prototypes.
  • One-off scripts: Ad hoc commands not yet productionized.
  • Alternate UIs: Optional frontends being compared.
  • Random side tools: Miscellaneous utilities with uncertain long-term value.

This layer is allowed to be messy - but it must be clearly labeled as experimental.
